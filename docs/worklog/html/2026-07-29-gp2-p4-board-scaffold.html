2. Factory backup first — and a native-USB read quirk

Before writing anything, backed up the full 16 MB factory image so the board can be restored. This surfaced a reliability quirk worth recording for all future P4 flashing here:

  • A single continuous read_flash 0 0x1000000 @460800 dropped mid-transfer ("Packet content transfer stopped"). 1 MB chunks: 14/16 fine, the 5–7 MB region failed every retry.
  • But a 64 KB read of that same region succeeds instantly — so the flash isn't bad; long continuous reads over this USB link drop. The failure just tends to land where the transfer has run longest.
  • Three stubborn 4 KB pages refused every stub-flasher read at both bauds. The fix: the ROM loader (esptool --no-stub) recovered all three — slow but reliable. (They held real data, so the 0xFF placeholder would have been a genuine loss.)

Backup read strategy — from one big read to reliable pieces

The escalation that got a complete, offset-correct 16 MB image over a flaky link.

Takeaway for all future P4 flashing on this board: prefer --no-stub for reads (or keep reads ≤64 KB); the stub flasher drops long transfers over this USB link. Writes/flash were fine with the stub. Backup lives in the session scratchpad (binary, not the repo) — owner to archive off-box.

3. The scaffold + the proof-of-life app

boards/guition-jc4880p443c/ mirrors the S3 board's structure:

  • sdkconfig.defaults — CONFIG_IDF_TARGET=esp32p4, 16 MB flash, external HEX PSRAM (200 MHz, the P4 default), console pinned to the native USB-Serial-JTAG as primary (this board's only host wire → single stdout, no dual-path stdio-lock surprise), and the v1.x rev-min fix (§4).
  • board.h — the same board-agnostic contract (board_lcd_* + 480×800 geometry), trimmed to the LCD core. Defines neither BOARD_HAS_SD nor BOARD_HAS_TOUCH yet, so those app paths compile out.
  • board.cpp — a stub: board_lcd_init logs + returns ESP_ERR_NOT_SUPPORTED; blit/fill no-op; board_lcd_rgb565 is a live pure function. Real ST7701S/MIPI-DSI bring-up lands here in GP-3.
  • README.md — per-board README matching the S3 board's format.

firmware/pico-e32-p4-hello/ is the minimal app: dumps chip/flash/PSRAM identity, calls the board display seam (stub), and heartbeats every second. Its only job is to prove the P4 path end to end.

The min-revision fork — early v1.x vs v3.x P4 (mutually exclusive)

IDF's own Kconfig: rev <3.0 and ≥3.0 support are mutually exclusive, "huge hardware difference", ≥3.0 "not compatible with 0.x and 1.x". The stock default rejects this board.

Implication for GP-3: because <3.0 and ≥3.0 P4 silicon differ in hardware, v3.x P4 reference code (DSI init, PSRAM timing) may not apply unchanged. Treat this board as early silicon.
